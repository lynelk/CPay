# Architecture Decision Records

ADRs are lightweight records for choices that shape CPay's architecture, operations, or integration contracts.

Create a new ADR when a decision changes one of these areas:

- payment channel routing
- provider adapter boundaries
- schema ownership or retention
- security model
- operational dashboards or alerting
- deployment or release process

Use the next sequential number and this structure:

```text
# ADR NNNN: Short Title

Date: YYYY-MM-DD
Status: Proposed | Accepted | Superseded

## Context

## Decision

## Consequences

## Follow-ups
```

Keep each ADR short enough that a new engineer can understand the trade-off in one pass.
